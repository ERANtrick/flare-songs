# BASE-B09：折り返しを許容するボタン検証

初回Ubuntu CIで、992px・日本語の歌唱履歴ボタンが2行になり、旧判定の「常に1行」に失敗しました。画面・traceでは幅306.203125px／高さ66px、横はみ出しなし。CSSは`white-space:normal`／`overflow-wrap:anywhere`で折り返しを許可しているため、製品CSSは変更せず、可読性・操作性の契約で検査します。

## 判定の変更

| 変更前 | 変更後 |
| --- | --- |
| 全ボタンの文字は必ず1行 | 行数は診断値。非空の文字が縦横ともラベル・ボタン内に収まる |
| 主に文字の左右端と横scroll幅を確認 | 縦横の文字rect、ラベルのscroll寸法、ボタンのscroll寸法を確認し、隠れた文字も検出 |
| アイコンや周囲との重なりは直接検査しない | 表示中のSVG／星がボタン内に収まり、各文字rectと重ならない。ボタン同士・見出し／メタ情報／画像との重複も検査 |
| 高さは992px未満48px、以上44px | 同じ下限を維持。enabled・pointer操作と、画面内のボタン中央が他要素で覆われていないことも確認 |
| お気に入りを切り替えたラベルも必ず1行 | 切替前・切替後・元へ戻した後の全ボタンへ同じ検査を適用し、aria-pressedとラベル変化も確認 |

rectや整数client寸法の比較は丸め誤差用に1 CSS pxだけ許容します。行数上限や文字切れを隠す設定は追加しません。既存の992px境界、サムネイル寸法、左右／上下配置、横スクロール、結果領域、長い曲名・配信タイトル、各種操作の検査は維持しています。

## 条件と測定

375／576／640／768／900／991／992／1280px × 日本語／英語 × light／dark × 通常／長文の64条件。各条件でお気に入り切替前・後・復元の3状態、計192レイアウトを測定します。375／991／992／1280pxは両テーマ・両言語・通常／長文の画面も保存します。

- `responsive-results.json`：行数・文字rect・ボタンrect・アイコン・ラベル・状態・衝突等の実測値。
- `responsive-probes.json`：下記の自己検査結果。
- `responsive-992-ja-*-normal.png`：Ubuntu成功時も両テーマの画面をsummary artifactへ保存。

## 判定自体の自己検査

BASE-B09内でテスト用DOMのスタイルだけを一時的に変え、最後に必ず復元します。製品ファイルには書き込みません。

1. ラベルの幅を狭めて実際に複数行にし、文字が収まれば正常と判定する。
2. ラベルを1pxの高さで切り取った状態を、文字の見切れとして検出する。
3. アイコンを文字上へ移した状態を、重なりとして検出する。
4. 隣のボタンへ重ねた状態を、ボタン干渉として検出する。
5. 操作対象を10pxの高さへ縮めた状態を、高さ不足として検出する。

不正状態は専用probeで明示的に作り、対応するassertionが失敗することを検査しています。通常の画面測定の失敗を握りつぶしたり、skipやretryで成功に変えたりする処理ではありません。独立したtest登録は増やさず、固定回帰の総数は210件のままです。
