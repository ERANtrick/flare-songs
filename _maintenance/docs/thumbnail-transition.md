# おまかせサムネイルのB150表示と回帰テスト

## 製品の表示契約

- 別URLに切り替えると、既存画像を直ちに透明にする。枠を16:9で保持し、新しい画像のloadとdecode成功後に表示する。
- 150ms未満で表示できる場合は案内を出さない。150msでまだ待機中なら控えめなマークと日英の案内を表示する。最低表示時間は設けない。
- 同URLの待機・成功状態を言語変更等で作り直さない。エラー後の言語変更でも再試行しない。別の抽選結果への切り替え時は再取得できる。
- URLなしは枠を非表示。実際のerror/decode失敗は枠と日英エラー案内を残す。次の正常画像で復旧する。
- 閉じる・カテゴリ変更・新しいURLへの抽選では古いハンドラと150msタイマーを外し、世代番号で遅れて完了するdecodeを無効化する。
- 時間だけでエラーにしない。15秒後に別の待機文言を出す案も検討したが、タイマー・翻訳・後片付けが増えるため採用していない。時間上限なしのload/error管理は正常な後着成功を受理する。通信が完了しなければ閉じる／次の抽選まで案内が続く。
- 通常カードの画像処理、全画像のlazy属性、抽選方式・保存形式は変更しない。

## 実行

通常のREADMEに従い `npm ci` とChromium導入後、`_maintenance` で `npm test`。新しいファイルも自動的に実行・集計される。Pagesは従来どおり `npm run test:pages`。

追加ケースだけを実行する場合（PowerShell）：

```powershell
$env:FLARE_RUN_DIR = Join-Path (Get-Location) ('artifacts/thumb-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
node node_modules/@playwright/test/cli.js test tests/browser/thumbnail.test.cjs --config=playwright.config.cjs
```

全体の合格判定・対象commitとfixture hash記録には `npm test` の結果を使う。

## 固定条件と証跡

`helpers/thumbnail.cjs` は現在checkoutの公開ファイルを動的な127.0.0.1ポートで配信する。通常のserverに追加した明示的なfixture応答だけを利用し、製品ファイルを書き換えない。テスト応答ではCSV_URLをローカル合成13列CSVへ置換し、Analyticsの外部scriptタグだけを除く。その他の製品scriptとBootstrap/PapaParseは実ファイルを使用する。vendorはHTTP200と正規hashを毎ケース確認する。

合成CSVは5曲（A/B/C/D/E）、C/Dは同URL、EはURLなし。画像は明確に識別できる単色SVG。曲名一覧の初期選択・固定乱数0を設定して、通常カードの先読みを避けながら既存の抽選ボタンで順に選ぶ。抽選アルゴリズム自体を置換しない。

Playwrightのrouteは使わず、HTTPキャッシュを有効のまま検証する。配信側で実レスポンスを保留・解放して遅延・逆転を作る。HTTP404とTCP切断は実サーバーで発生させる。外部通信・pageerrorは失敗とし、既知エラーも状態遷移と復旧を検証する。

キャッシュ済みimageの再表示ではChromiumが既存のデコード結果を再利用し、ResourceTiming項目を追加しない場合がある。B05では独立したforce-cache取得の転送量0とサーバー到着件数の不変を確認する。ソケット切断はブラウザ内部で再送されるため、B08では初回到着数を1固定にせず、エラー確定後の言語変更で増加しないことを検証する。

150ms・20秒の境界はPlaywright Clockで制御する。実ネットワーク速度の測定ではない。B01/B08/B09/B18は画像証跡、各ケースは通信記録をPlaywrightレポートへ添付する。失敗時は既存設定に従いtraceとスクリーンショットを保存する。
